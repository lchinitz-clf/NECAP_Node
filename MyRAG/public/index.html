Discards store.json and rebuilds it from scratch by re-extracting, re-chunking, and re-embedding every file already uploaded into this workspace. Use this if the index seems out of sync with what's actually here, or if store.json is missing or looks wrong. 1. Embed a document

Uploaded to the server and saved under this workspace before extraction starts — the same flow this UI will use once the server isn't your own computer anymore.

Smaller chunks retrieve more precisely but carry less surrounding context per match; overlap repeats a few trailing words at the start of the next chunk so a sentence spanning a boundary isn't lost entirely. A fixed internal 1800-character cap per chunk always applies underneath this setting too, to stay safely under the embedding model's context limit — so raising chunk size much past ~300-400 words on ordinary prose won't actually produce bigger chunks, only smaller ones (below that) will take effect. Applies to this one document; existing embedded documents in this workspace keep whatever size they were embedded with.

2. Ask a question

Optional if you select an ideal-proposal topic below — in that case, whatever you type here is added as extra guidance on top of the topic's own criteria, rather than replacing it. Required otherwise.

Selecting a topic replaces plain Q&A with a comparison: the topic's own ideal attributes (from idealProposals.json) become the actual question sent for retrieval, so the chunks pulled from the reviewed document are chosen with those attributes in mind, not just whatever you separately typed above. Consider raising "Chunks to retrieve (topK)" below for a comparison — checking several distinct attributes usually benefits from more retrieved context than a single factual question does.

Lower (0) sticks closely to the retrieved chunks and answers the same way every time; higher gets more varied and creative but more prone to drifting from the source text — for document Q&A, low is usually right.

Leave blank for no cap (the model stops on its own, or when it runs out of context). Set this to bound how long generation can run — useful on modest local hardware, or to stop a model from rambling well past a direct answer.

For reasoning models (e.g. deepseek-r1) that work through a chain-of-thought before answering — shown below the answer, collapsed by default. Unchecking this tells Ollama to skip that step entirely rather than just hiding it, which is faster and also avoids max-answer-length being spent entirely on reasoning before any real answer text. Models that don't support thinking (e.g. llama models) ignore this either way.
