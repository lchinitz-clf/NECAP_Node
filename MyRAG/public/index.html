ⓘ Usually between 0 and 1, with 0 meaning always consistent. Higher values allow more variety in how the answer is worded, but can drift further from the source text.
ⓘ How strongly the AI model is discouraged from repeating itself. Leave blank to use the model's own default (usually 1.1). Weaker or smaller models can sometimes get stuck restating a slight variant of what they just said instead of finishing — several near-duplicate paragraphs in a row instead of one answer. If you see that happen, try raising this to around 1.3-1.4. Values much above that can start to hurt answer quality by avoiding legitimate repeated words (like a document's own terminology), so raise it gradually rather than jumping straight to the maximum.
ⓘ Roughly limits how long the answer can be. Leave blank for no limit — the answer will stop on its own once it's complete.
ⓘ How much room the AI model has for your question, the searched blocks, and its answer, all combined. Leave blank to use the model's own default — commonly 4096. Raising this lets you search more blocks or get longer answers without running out of room, but uses more memory; how much depends on the model. If a question fails outright with an error mentioning "context size," this is usually too low for how much you're asking it to work with.
ⓘ Some AI models work through their reasoning before giving a final answer — viewable by opening "Show reasoning" below the answer. Turning this off skips that step, which is usually faster. Models that don't support this ignore the setting either way.
ⓘ Only matters when comparing against an ideal proposal below. A topic with many attributes can otherwise fold all of them into one very large question at once. Enter a number to split it into smaller batches instead — "1" asks about each attribute one at a time, "5" asks in groups of 5, and so on — which both keeps each call smaller and lets each batch's search focus on just its own attributes. Leave blank to ask about every attribute in a single call, as before. Smaller batches take more calls (and somewhat longer overall) but retrieve more relevant material per attribute and are also parsed more reliably into the per-attribute results table and CSV below.
